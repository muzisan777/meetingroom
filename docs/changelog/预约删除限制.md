**新增验证**:

```python
@app.delete("/api/bookings/{booking_id}")
async def delete_booking(booking_id: int, db: Session = Depends(get_db), current_user: User = Depends(get_current_user)):
    """删除预约"""
    booking = db.query(Booking).filter(Booking.id == booking_id).first()
    if not booking:
        raise HTTPException(status_code=404, detail="预约不存在")
    
    # 已完成的预约不能删除
    from datetime import datetime
    if booking.end_time < datetime.now():
        raise HTTPException(status_code=400, detail="已完成的预约不能删除")
    
    # 普通用户只能删除自己的预约
    if not current_user.is_admin and booking.user_id != current_user.id:
        raise HTTPException(status_code=403, detail="无权限删除该预约")
    
    db.delete(booking)
    db.commit()
    return {"message": "删除成功"}
```

## 判断逻辑

### 预约状态判断

```javascript
const getBookingStatus = (booking) => {
  const now = dayjs()
  const startTime = dayjs(booking.start_time)
  const endTime = dayjs(booking.end_time)
  
  if (now.isBefore(startTime)) return '待开始'
  if (now.isBetween(startTime, endTime)) return '使用中'
  return '已完成'
}
```

**状态定义**:
- **待开始**: 当前时间 < 开始时间
- **使用中**: 开始时间 ≤ 当前时间 ≤ 结束时间
- **已完成**: 当前时间 > 结束时间

### 删除权限

| 预约状态 | 删除按钮 | 点击效果 |
|---------|---------|---------|
| 待开始 | ✅ 可点击 | 弹出确认对话框 |
| 使用中 | ✅ 可点击 | 弹出确认对话框 |
| 已完成 | ❌ 灰色禁用 | 显示"不可删除" |
| 已取消 | ❌ 灰色禁用 | 显示"不可删除" |

## 三层防护

### 1. UI 层（按钮禁用）
- 已完成的预约删除按钮显示为灰色
- 按钮文字变为"不可删除"
- 用户无法点击

### 2. 逻辑层（前端验证）
```javascript
if (isBookingCompleted(booking)) {
  ElMessage.warning('已完成的预约不能删除')
  return
}
```
- 即使绕过 UI 限制，点击也会提示警告
- 不会发送删除请求

### 3. 数据层（后端验证）
```python
if booking.end_time < datetime.now():
  raise HTTPException(status_code=400, detail="已完成的预约不能删除")
```
- 最后一道防线
- 防止直接调用 API 删除
