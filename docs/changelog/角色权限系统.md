# 角色驱动权限系统

## 修改时间
2026-05-11

## 修改内容

### 概述
将原有的二元权限模型（`is_admin` 布尔值）升级为角色驱动的细粒度权限系统。管理员可通过 UI 动态创建角色，并为每个角色配置「模块 × 操作」的权限矩阵（增删改查）。

### 后端改动

#### 新增文件
| 文件 | 说明 |
|------|------|
| `backend/permissions.py` | 权限检查模块，提供 `check_user_permission()` 和 `require_permission()` |

#### 修改文件
| 文件 | 改动 |
|------|------|
| `backend/models.py` | 新增 `Role`、`RolePermission` 模型；`User` 表添加 `role_id` 可空外键 |
| `backend/schemas.py` | 新增 `RoleCreate/Update/Response`、`PermissionCreate/Response`、`RolePermissionsUpdate` |
| `backend/main.py` | 新增角色 CRUD 和权限管理 API 共 7 个接口；登录和 `/me` 接口返回 `role_name` 和 `permissions`；启动时自动创建默认角色 |

#### 新增 API 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/roles` | 获取角色列表（含用户数） |
| GET | `/api/roles/{id}` | 获取角色详情 |
| POST | `/api/roles` | 创建角色 |
| PUT | `/api/roles/{id}` | 更新角色信息 |
| DELETE | `/api/roles/{id}` | 删除角色 |
| GET | `/api/roles/{id}/permissions` | 获取角色权限列表 |
| PUT | `/api/roles/{id}/permissions` | 批量更新角色权限 |

#### 数据模型

```
roles
├── id (PK)
├── name (UNIQUE)
├── description
├── is_active
└── created_at

role_permissions
├── id (PK)
├── role_id (FK → roles.id)
├── module      # users/rooms/bookings/items/borrowings/organizations/logs/roles
└── action      # create/read/update/delete

users (新增字段)
├── role_id (FK → roles.id, nullable)
```

### 权限模块定义

| 模块 | 可用操作 |
|------|----------|
| users (用户管理) | create, read, update, delete |
| organizations (组织管理) | create, read, update, delete |
| rooms (会议室管理) | create, read, update, delete |
| bookings (预约管理) | create, read, update, delete |
| items (物品管理) | create, read, update, delete |
| borrowings (借用管理) | create, read, update, delete |
| logs (系统日志) | read |
| roles (角色管理) | read |

### 权限判定逻辑

```
用户请求 → is_admin = true? → 全部放行
                              ↓ false
                         有 role_id? → 查询 role_permissions
                              ↓ 否
                         默认权限（查看、自预约/自借用）
```

### 默认角色

| 角色 | 说明 | 权限 |
|------|------|------|
| 超级管理员 | 系统初始化创建 | 全部 8 模块 × 可用操作（26 条） |
| 普通用户 | 系统初始化创建 | rooms/items 查看 |

### 配置说明

- 启动时会自动**删除旧数据库并重建**（开发环境），生产环境需手动迁移
- 管理员 `admin` 用户自动关联"超级管理员"角色
- 现有 `is_admin = true` 用户不受角色约束，仍拥有全部权限

## v1.2 更新：菜单与页面动态权限联动

### 修改时间
2026-05-11

### 概述
将权限系统与前端菜单和页面按钮联动：侧边栏菜单根据用户的 `read` 权限动态显示，页面内的新增/编辑/删除按钮根据 `create/update/delete` 权限动态显示。

### 改动详情

#### `src/stores/user.js`
- 新增 `showMenuItem(module)` — 根据 `hasPermission(module, 'read')` 决定菜单可见性
- `hasPermission()` 现在对无角色用户返回默认权限集，保证向后兼容

#### `src/router/index.js`
- 所有受权限控制的路由添加 `meta.module` 字段
- 路由守卫新增模块权限检查：无 `read` 权限自动跳转 `/dashboard`

#### `src/views/Layout.vue`
- 侧边栏全部 8 个菜单项从 `v-if="userStore.isAdmin"` 改为 `v-if="userStore.showMenuItem('module')"`
- 移除 `userStore.isAdmin` 依赖的菜单文本区分

#### 页面按钮权限映射

| 页面 | 新增(Create) | 编辑(Update) | 删除(Delete) | 其他 |
