# 会议室预约系统 — 完整测试计划

## 一、测试工具及依赖

| 类型 | 工具 | 用途 |
|------|------|------|
| E2E 浏览器自动化 | **Playwright** | 直接操控本地 Chrome/Firefox，模拟用户点击、输入、选择等真实操作 |
| 后端 API 测试 | **pytest + httpx AsyncClient** | 测试所有 REST API 接口 |
| 前端单元测试 | **vitest + @vue/test-utils** | 组件逻辑、Pinia store、工具函数 |
| 断言库 | **内置 + chai** | Playwright 自带断言；pytest 用 assert |

## 二、安装命令

```bash
# Playwright
cd frontend

npx playwright install chromium

# 后端测试
cd ../backend
```

## 四、测试数据策略

每次 E2E 测试运行前自动执行：
1. 调用 `backend/reset_db.py` 重置 SQLite 数据库
2. 调用 `backend/init_test_data.py` 注入标准种子数据
3. Playwright 的 `globalSetup` 钩子自动完成以上两步

**种子数据清单：**
- 管理员: `admin / admin123`
- 普通用户: `user1 / password123`
- 3 个会议室（不同容量、位置、设施）
- 2 个可借用物品（投影仪、白板笔）
- 1 个部门（技术部）

## 六、后端 API 测试（pytest）重点

`backend/tests/conftest.py` 提供的关键 fixtures：
- `async_client()` — 创建测试用 AsyncClient
- `db_session()` — 独立的测试数据库事务，测试结束后回滚
- `auth_headers(user)` — 生成 JWT token header
- `admin_headers` — admin 的认证 header
- `test_db()` — 每次测试前重置数据库

测试覆盖（约 80+ 测试用例）：
- 认证：登录成功/失败/密码错误/用户不存在/token过期/无token访问
- 会议室：普通用户能查看但不能创建/修改/删除
- 预订：创建成功/时间段冲突/取消/状态流转/按用户筛选/按日期范围筛选
- 物品：库存扣减原子性/可用数量不低于0
- 借用：借用时库存减少/归还时库存恢复/超期状态自动标记
- 用户：admin 可 CRUD/普通用户不可/唯一性约束
- 角色：权限分配验证/角色删除时关联用户处理
- 日志：分页/按类型筛选/关键词搜索

## 九、运行命令

```bash
# 启动服务（新窗口）
# 终端1: 后端
cd backend && uvicorn main:app --reload --port 8000

# 终端2: 前端
cd frontend && npm run dev

# 运行测试
cd backend && pytest tests/ -v                         # 后端 API 测试
cd frontend && npx vitest run                          # 前端单元测试
cd frontend && npx playwright test                     # E2E 测试（需后端+前端已启动）

# 一条命令运行全部（新增到 package.json scripts）
"test": "npx playwright test"
"test:unit": "vitest run"
```
