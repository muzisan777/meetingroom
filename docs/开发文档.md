## 1. 项目概述

### 1.1 项目背景
会议室管理系统是为企业/组织设计的会议室和物品借用管理平台，提供会议室预约、物品借用、使用记录查询等功能。

### 1.2 核心功能
- **会议室管理**: 会议室信息维护、状态管理
- **预约管理**: 会议室预约、取消、查询
- **物品管理**: 可借用物品管理、库存管理
- **借用管理**: 物品借用、归还、记录查询
- **用户管理**: 用户认证、权限管理、个人信息

### 1.3 访问地址
| 环境 | 地址 | 说明 |
|------|------|------|
| 前端 | http://localhost:3000 | Vue 3 开发服务器 |
| 后端 API | http://localhost:8000 | FastAPI 服务 |
| API 文档 | http://localhost:8000/docs | Swagger UI |
| API 文档 (备用) | http://localhost:8000/redoc | ReDoc |

## 3. 用户角色与权限

### 3.1 权限模型演进

系统从 v1.0 的简单二元权限（`is_admin`）升级为 v1.1 的**角色驱动权限系统**。

| 版本 | 模型 | 说明 |
|------|------|------|
| v1.0 | `is_admin` 布尔值 | 管理员 vs 普通用户 |
| v1.1 | 角色 + 权限矩阵 | 支持自定义角色和细粒度权限 |

详细设计文档见 [`docs/权限系统.md`](./权限系统.md)。

### 3.2 角色定义

| 角色 | 说明 | 创建方式 |
|------|------|----------|
| 超级管理员 | 拥有系统全部权限（后台固定） | 系统初始化自动创建 |
| 普通用户 | 基础的查看和预约借用权限 | 系统初始化自动创建 |
| 自定义角色 | 根据业务需要灵活配置 | 管理员在 UI 创建 |

### 3.3 权限模块

| 模块 | 可用操作 | 说明 |
|------|----------|------|
| 用户管理 (users) | 增删改查 | 管理用户账号 |
| 组织管理 (organizations) | 增删改查 | 管理部门/组织 |
| 会议室管理 (rooms) | 增删改查 | 管理会议室资源 |
| 预约管理 (bookings) | 增删改查 | 管理预约记录 |
| 物品管理 (items) | 增删改查 | 管理可借物品 |
| 借用管理 (borrowings) | 增删改查 | 管理借用记录 |
| 系统日志 (logs) | 仅查看 | 查看操作和错误日志 |
| 角色管理 (roles) | 仅查看 | 查看角色列表 |

### 3.4 权限判定规则

```
1. is_admin = true → 全部放行（不受角色约束）
2. 用户分配了角色 → 查询 role_permissions 表判定
3. 无角色且非管理员 → 保持 v1.0 默认行为
```

### 3.5 测试账号

| 用户名 | 密码 | 角色 | 用途 |
|--------|------|------|------|
| `admin` | `admin@123` | 超级管理员 (内置) | 系统管理测试 |

### 3.6 日志系统

系统已集成完整的日志记录功能：

| 日志类型 | 说明 | 访问权限 |
|----------|------|----------|
| 操作日志 (action.log) | 记录用户操作行为 | 拥有 `logs:read` 权限的用户 |
| 错误日志 (error.log) | 记录系统错误信息 | 拥有 `logs:read` 权限的用户 |
| 访问日志 (access.log) | 记录 API 访问记录 | 拥有 `logs:read` 权限的用户 |

**记录的操作**:
- 用户登录/登出
- 创建/更新/删除会议室
- 创建/取消预约
- 借用/归还物品
- 用户管理操作
- 组织管理操作
- 物品管理操作
- 角色管理操作

## 4. 功能模块详解

### 4.1 用户认证模块 (Auth)

#### 4.1.1 功能目标
- 提供用户登录/登出功能
- 基于 JWT 的 Token 认证
- 保护需要认证的 API 接口

#### 4.1.2 业务流程

```
用户输入账号密码
    ↓
前端调用 POST /api/auth/login
    ↓
后端验证账号密码
    ├─ 失败 → 返回 401 + 错误信息
    └─ 成功 → 生成 JWT Token
    ↓
前端保存 Token 到 localStorage
    ↓
后续请求携带 Authorization: Bearer <token>
```

#### 4.1.3 页面元素
- **登录页** (`/login`)
  - 用户名输入框 (必填)
  - 密码输入框 (必填)
  - 登录按钮
  - 错误提示区域

#### 4.1.4 成功结果
- 跳转至首页 (`/`)
- 显示欢迎消息
- 导航栏显示用户信息

#### 4.1.5 错误提示

| 错误场景 | HTTP 状态码 | 提示信息 |
|---------|-----------|---------|
| 用户名或密码错误 | 401 | "用户名或密码错误" |
| 用户已被禁用 | 400 | "用户已被禁用" |
| Token 过期 | 401 | "登录已过期，请重新登录" |
| 无权访问 | 403 | "无权访问" |

1. 开始时间 < 结束时间
2. 开始时间 > 当前时间
3. 结束时间 ≤ 20:00
4. 时间段未被占用

### 4.4 预约管理模块 (Bookings)

#### 4.4.1 功能目标
- 创建、查看、取消预约
- 时间冲突检测
- 预约状态管理

#### 4.4.2 预约状态

| 状态 | 标识 | 说明 | 可取消 |
|------|------|------|--------|
| 待开始 | `pending` | 预约时间未到 | ✅ |
| 使用中 | `confirmed` | 当前时间在预约时间段内 | ✅ |
| 已完成 | `completed` | 预约时间已结束 | ❌ |
| 已取消 | `cancelled` | 用户主动取消 | ❌ |

**状态判断逻辑**:
```python
def get_booking_status(booking):
    if booking.status == 'cancelled':
        return '已取消'
    
    now = datetime.now()
    if now > booking.end_time:
        return '已完成'
    elif now >= booking.start_time:
        return '使用中'
    else:
        return '待开始'
```

#### 4.4.3 预约列表页

**筛选条件**:
| 筛选项 | 选项值 |
|--------|--------|
| 状态 | 全部/待开始/使用中/已完成/已取消 |
| 日期范围 | 日期选择器 |
| 会议室 | 下拉选择 |

**列表字段**:
| 字段 | 说明 |
|------|------|
| 会议室 | 会议室名称 |
| 日期 | 预约日期 |
| 时间 | 开始时间 - 结束时间 |
| 事由 | 预约用途 |
| 预约人 | 用户名 |
| 部门 | 用户部门 |
| 状态 | 状态标签 |
| 操作 | 取消按钮 (仅待开始/使用中) |

#### 4.4.4 取消预约

**前置条件**:
- 预约状态为"待开始"或"使用中"
- 当前时间 < 预约结束时间

**确认对话框**:
```
确定要取消该预约吗？

取消后该时间段将释放，其他用户可以预约。

[取消]  [确定]
```

**成功结果**:
- 状态变更为"已取消"
- 显示"取消成功"提示
- 列表刷新

**错误提示**:

| 错误场景 | 提示信息 |
|---------|---------|
| 预约不存在 | "预约不存在" |
| 预约已完成 | "已完成的预约不能取消" |
| 无权操作 | "只能取消自己的预约" |

#### 4.6.2 借用流程

```
用户选择物品
    ↓
填写借用信息
    ├─ 借用日期 (默认今天)
    ├─ 应还日期 (默认 +7 天)
    └─ 用途说明
    ↓
提交借用申请
    ↓
检查库存
    ├─ 库存不足 → 提示错误
    └─ 库存充足 → 创建记录
    ↓
扣减可用库存
    ↓
显示借用成功
```

#### 4.6.3 借用对话框

**验证规则**:

**状态定义**:
| 状态 | 条件 |
|------|------|

| 已归还 | `actual_return_date ≠ null` |

#### 4.6.5 归还功能

**归还对话框**:
```
确认归还物品？

物品：投影仪
借用日期：2026-03-10 14:30
应还日期：2026-03-17 14:30

[取消]  [确认归还]
```

**归还逻辑**:
```python
def return_item(borrowing_id, current_user):
    borrowing = get_borrowing(borrowing_id)
    
    # 检查权限
    if borrowing.user_id != current_user.id and not current_user.is_admin:
        raise HTTPException(403, "无权归还他人物品")
    
    # 更新记录
    borrowing.actual_return_date = datetime.now()
    
    # 恢复库存
    item = borrowing.item
    item.available_quantity += 1
    
    db.commit()
```

**成功结果**:
- 状态变更为"已归还"
- 显示"归还成功"提示
- 可用数量 +1
- 列表刷新

**错误提示**:

| 错误场景 | 提示信息 |
|---------|---------|
| 物品不存在 | "物品不存在" |
| 库存不足 | "库存不足，无法借用" |
| 物品不可借 | "该物品暂不可借" |
| 无权归还 | "只能归还未自己的物品" |
| 已归还 | "该物品已归还" |

### 7.3 前端错误处理

#### Axios 响应拦截器

```javascript
// frontend/src/api/request.js

request.interceptors.response.use(
  response => {
    return response.data
  },
  error => {
    if (error.response) {
      const { status, data, config } = error.response
      
      if (status === 401) {
        // 登录接口的 401 显示具体错误
        if (config.url && config.url.includes('/auth/login')) {
          ElMessage.error(data.detail || '用户名或密码错误')
        } else {
          // 其他接口的 401 表示 token 过期
          ElMessage.error('登录已过期，请重新登录')
          localStorage.removeItem('token')
          localStorage.removeItem('user')
          window.location.href = '/login'
        }
      } else if (status === 403) {
        ElMessage.error('无权访问')
      } else if (status === 404) {
        ElMessage.error('资源不存在')
      } else {
        ElMessage.error(data.detail || '请求失败')
      }
    } else {
      ElMessage.error('网络错误')
    }
    return Promise.reject(error)
  }
)
```

function hasPermission(module, action) {
  if (isAdmin.value) return true                              // 管理员全放行
  if (!userInfo.value?.role_id)                                // 无角色 → 默认权限
    return defaultPerms.some(p => p.module === module && p.action === action)

### A. 常见问题 (FAQ)

**Q: 预约提交后没有反应？**
A: 打开浏览器开发者工具 (F12) 查看 Console 和 Network 标签，检查是否有错误信息。常见问题：
- 后端服务未启动
- 时间段已被占用
- 时间格式不正确

**Q: 登录后跳转回登录页？**
A: 可能是 Token 存储问题，尝试：
1. 清除浏览器缓存
2. 检查 localStorage 中是否有 token
3. 确认后端 SECRET_KEY 配置正确

**Q: 如何添加新管理员？**
A: 使用现有管理员账号登录，进入用户管理页面添加新用户并勾选"管理员"选项。
