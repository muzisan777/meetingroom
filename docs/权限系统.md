## 1. 设计概述

### 1.1 设计目标

- 管理员可通过 UI 动态创建/删除角色
- 每个角色的权限以「模块 × 操作」矩阵形式配置（增删改查）
- 向后兼容：现有 `is_admin` 标识不废弃，管理员自动拥有全部权限
- 最小代码改动：不破坏已有数据模型和 API 结构

### 1.2 核心概念

| 概念 | 说明 |
|------|------|
| **角色 (Role)** | 权限的集合，可分配给多个用户 |
| **权限 (Permission)** | 单个「模块 + 操作」组合，如 `rooms:create` |
| **模块 (Module)** | 功能域，如用户管理、会议室管理 |
| **操作 (Action)** | 增 (`create`)、删 (`delete`)、改 (`update`)、查 (`read`) |

### 1.3 权限判定链

```
用户请求
  ↓
is_admin = true? ──→ 全部放行（超级管理员）
  ↓ false
有 role_id? ──→ 查询 role_permissions 表
  ↓ 无          ↓ 有
默认权限        判 module + action 是否存在
(查看会议室/     ↓ 存在 → 放行
 物品, 自预约)   ↓ 不存在 → 403
```

## 2. 数据模型

### 2.1 角色表 (roles)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Integer PK | 主键 |
| name | String(50) UNIQUE | 角色名称 |
| description | String(200) | 角色描述 |
| is_active | Boolean | 是否启用，默认 `true` |
| created_at | DateTime | 创建时间 |

### 2.2 权限表 (role_permissions)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Integer PK | 主键 |
| role_id | Integer FK → roles.id | 所属角色 |
| module | String(50) | 模块名 |
| action | String(20) | 操作名 |

`(role_id, module, action)` 联合确保不重复。

### 2.3 用户表扩展 (users)

| 新增字段 | 类型 | 说明 |
|----------|------|------|
| role_id | Integer FK → roles.id, nullable | 用户关联的角色 |

`role_id` 为可空字段，不分配角色的用户保持原有行为不变。

### 2.4 关系图

```
┌──────────┐       ┌──────────────────┐       ┌──────────────┐
│   Role   │──1:N──│  RolePermission  │       │    User      │
│──────────│       │──────────────────│       │──────────────│
│ id       │       │ id               │       │ id           │
│ name     │       │ role_id (FK)     │       │ role_id (FK) │──N:1──┐
│ desc     │       │ module           │       │ is_admin     │      │
└──────────┘       │ action           │       └──────────────┘      │
                   └──────────────────┘                            │
                    ┌───────────────────────────────────────────────┘
                    │
               ┌────┴──────┐
               │  Role     │
               └───────────┘
```

### 2.5 ORM 定义

```python
class Role(Base):
    __tablename__ = "roles"
    id = Column(Integer, primary_key=True, index=True)
    name = Column(String(50), unique=True, nullable=False)
    description = Column(String(200))
    is_active = Column(Boolean, default=True)
    created_at = Column(DateTime, default=datetime.now)

    users = relationship("User", back_populates="role")
    permissions = relationship("RolePermission", back_populates="role", cascade="all, delete-orphan")


class RolePermission(Base):
    __tablename__ = "role_permissions"
    id = Column(Integer, primary_key=True, index=True)
    role_id = Column(Integer, ForeignKey("roles.id"), nullable=False)
    module = Column(String(50), nullable=False)
    action = Column(String(20), nullable=False)

    role = relationship("Role", back_populates="permissions")
```

## 3. 权限检查流程

### 3.1 后端检查函数 (`backend/permissions.py`)

```python
def check_user_permission(db, user, module, action):
    if user.is_admin:
        return True                          # 超管全放行
    if module not in MODULE_ACTIONS:
        return False                         # 非法模块
    if action not in MODULE_ACTIONS[module]:
        return False                         # 非法操作
    if not user.role_id:
        return False                         # 无角色

    perm = db.query(RolePermission).filter(
        RolePermission.role_id == user.role_id,
        RolePermission.module == module,
        RolePermission.action == action
    ).first()
    return perm is not None
```

### 3.2 FastAPI 依赖注入

```python
from permissions import require_permission

# 在路由中使用
@app.get("/api/users")
async def list_users(
    current_user = Depends(require_permission("users", "read"))
):
    ...

# 或保留原有管理员检查（向后兼容）
@app.delete("/api/organizations/{id}")
async def delete_org(
    current_user = Depends(get_current_admin_user)
):
    ...
```

### 3.3 前端检查 (`frontend/src/stores/user.js`)

```javascript
// 在组件中使用
const userStore = useUserStore()

if (userStore.hasPermission('rooms', 'create')) {
  // 显示"添加会议室"按钮
}
```

## 4. 模块与操作矩阵

| 模块 (module) | 标签 | create | read | update | delete |
|---------------|------|--------|------|--------|--------|
| users | 用户管理 | ✅ | ✅ | ✅ | ✅ |
| organizations | 组织管理 | ✅ | ✅ | ✅ | ✅ |
| rooms | 会议室管理 | ✅ | ✅ | ✅ | ✅ |
| bookings | 预约管理 | ✅ | ✅ | ✅ | ✅ |
| items | 物品管理 | ✅ | ✅ | ✅ | ✅ |
| borrowings | 借用管理 | ✅ | ✅ | ✅ | ✅ |

| roles | 角色管理 | — | ✅ | — | — |

## 5. 后端 API

### 5.1 角色 CRUD

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| `GET` | `/api/roles` | 获取角色列表（含用户数） | 管理员 |
| `GET` | `/api/roles/{id}` | 获取角色详情 | 管理员 |
| `POST` | `/api/roles` | 创建角色 | 管理员 |
| `PUT` | `/api/roles/{id}` | 更新角色信息 | 管理员 |
| `DELETE` | `/api/roles/{id}` | 删除角色（有用户时禁止） | 管理员 |

### 5.2 角色权限管理

| 方法 | 路径 | 说明 | 权限 |
|------|------|------|------|
| `GET` | `/api/roles/{id}/permissions` | 获取角色的权限列表 | 管理员 |
| `PUT` | `/api/roles/{id}/permissions` | 批量更新角色的权限 | 管理员 |

### 5.3 请求/响应示例

#### 创建角色

```http
POST /api/roles
Authorization: Bearer <token>
Content-Type: application/json

{
  "name": "会议室管理员",
  "description": "可管理会议室和预约"
}
```

**响应**:
```json
{
  "id": 3,
  "name": "会议室管理员",
  "description": "可管理会议室和预约",
  "is_active": true,
  "user_count": 0,
  "created_at": "2026-05-11T10:00:00"
}
```

#### 更新角色权限（全量覆盖）

```http
PUT /api/roles/3/permissions
Authorization: Bearer <token>
Content-Type: application/json

{
  "permissions": [
    {"module": "rooms", "action": "read"},
    {"module": "rooms", "action": "create"},
    {"module": "rooms", "action": "update"},
    {"module": "rooms", "action": "delete"},
    {"module": "bookings", "action": "read"},
    {"module": "bookings", "action": "create"},
    {"module": "bookings", "action": "update"},
    {"module": "bookings", "action": "delete"}
  ]
}
```

### 6.2 权限检查工具 (`src/stores/user.js`)

```javascript
const permissions = computed(() => userInfo.value?.permissions || [])

function hasPermission(module, action) {
  if (isAdmin.value) return true            // 管理员放行
  return permissions.value.some(
    p => p.module === module && p.action === action
  )
}
```

### 6.3 前端路由守卫

```
meta: { requiresAuth: true, requiresAdmin: true, title: '角色管理' }
```

路由守卫保持不变：`requiresAdmin: true` 的路径仅管理员可访问。

## 7. 默认角色

系统启动时自动创建两个默认角色：

### 7.1 超级管理员

| 属性 | 值 |
|------|------|
| 名称 | 超级管理员 |
| 描述 | 拥有系统全部权限 |
| 权限 | 全部 8 个模块的全部可用操作（共 26 条权限） |
| 关联用户 | 内置 `admin` 用户 |

### 7.2 普通用户

| 属性 | 值 |
|------|------|
| 名称 | 普通用户 |
| 描述 | 拥有基础的查看和预约借用权限 |
| 权限 | `rooms:read`, `items:read` |
| 备注 | 预约和借用的创建/查看通过 API 中的 owner 检查实现，不由权限系统控制 |

## 8. 使用指南

### 8.1 管理员操作流程

1. 登录 `admin` 账号
2. 进入侧边栏「角色管理」
3. 点击「添加角色」，填写角色名称和描述
4. 在权限矩阵中勾选该角色应拥有的权限
5. 点击「保存」
6. 进入「用户管理」，为用户分配角色

### 8.2 为已有用户分配角色

1. 进入「用户管理」
2. 编辑目标用户
3. 在 `role_id` 字段选择要分配的角色（后端需要增加该字段到用户编辑界面）
4. 保存后该用户下次登录将携带新的权限

### 8.3 页面与按钮权限联动

权限不仅用于 API 后端校验，还控制前端 UI 的可见性：

| 控制层级 | 控制条件 | 效果 |
|----------|---------|------|
| 侧边栏菜单 | `showMenuItem(module)` = `hasPermission(module, 'read')` | 无 read 权限的模块从菜单中消失 |
| 路由守卫 | `router.beforeEach` 检查 `meta.module` 的 read 权限 | 直接访问 URL 时重定向到首页 |
| 页面按钮 | `hasPermission(module, action)` | 新增/编辑/删除 按钮仅在用户有对应权限时显示 |

**每个页面的按钮与权限映射：**

| 页面 | 新增(Create) | 编辑(Update) | 删除(Delete) | 其他操作 |
|------|-------------|-------------|-------------|---------|
| 会议室管理 rooms | `rooms:create` | `rooms:update` | `rooms:delete` | 预约 → `bookings:create` |
| 预约管理 bookings | `bookings:create` | — | — | 取消 → `bookings:update` |
| 物品管理 items | `items:create` | `items:update` | `items:delete` | 借用 → `borrowings:create` |
| 借用管理 borrowings | — | — | — | 归还 → `borrowings:update` |
| 组织管理 organizations | `organizations:create` | `organizations:update` | `organizations:delete` | — |
| 用户管理 users | `users:create` | `users:update` | `users:delete` | — |
| 角色管理 roles | `roles:create` | — | `roles:delete` | — |
| 系统日志 logs | — | — | — | 无 CRUD 按钮 |

> 注意：`bookings:create` 控制"预约"和"新建预约"按钮，`borrowings:create` 控制"借用"按钮，即一个操作对应一个权限模块。

### 8.4 注意事项

- **不可删除「超级管理员」角色**：前端和后端均做了保护
- **有用户的角色不可删除**：需先解除所有用户的角色关联
- **权限修改后需重新登录**：权限信息在登录时加载并缓存在 localStorage
- **管理员不受角色约束**：`is_admin = true` 的用户跳过所有权限检查
